# Festivals

Yaadein ships a small festival calendar so that a Diwali-day pick is titled "Diwali 2024 with Aai", Relive can show
"This Diwali, years ago", the daily reminder can say "Happy Diwali! Add today's photos to Yaadein", and the timeline
can be filtered to one festival across every year. Nothing is computed from the moon or downloaded: the dates are a
bundled table and the app stays 100 % offline.

## The table

`core/domain/src/main/resources/festivals/festivals.csv` — one row per festival per year, `festival,year,yyyy-mm-dd`,
for **2010 to 2035** (26 rows per festival, 390 rows in all). Blank lines and `#` comments are skipped; a row with an
unknown festival key, a date that does not parse, or a year that does not match the date is ignored
(`Festivals.parse`). The table is a plain JVM classpath resource, so the pure Kotlin tests in `core/domain` read the
same file the app does (`Festivals.bundled()`), and `FestivalsTest` asserts that every year 2010–2035 has every
festival.

### Source

Generated by `scripts/festivals/generate.py` from the [`holidays`](https://pypi.org/project/holidays/) Python
package (MIT licence; the version used is written in the first line of the CSV), using India's public and optional
holiday categories. To regenerate:

```
pip install holidays
python3 scripts/festivals/generate.py > core/domain/src/main/resources/festivals/festivals.csv
```

Notes on the upstream data:

- **Islamic dates for the far years are estimates.** `holidays` carries published calendars for Eid al-Fitr and Eid
  al-Adha up to a point and marks later years "(estimated)"; the generator strips that marker and keeps the date. The
  real day depends on the moon sighting and can differ by a day; the festival windows below absorb that.
- Hindu lunar festivals (Diwali, Holi, Ganesh Chaturthi, Dussehra, Raksha Bandhan, Janmashtami, Gudi Padwa, Guru
  Nanak Jayanti) come from the package's published Indian calendar. Where the package lists several names for one
  day, the generator matches the main day only (`Diwali (Deepavali)`, not Naraka Chaturdashi; `Holi`, not Holika
  Dahan; `Dussehra`, not `Dussehra (Saptami)`; `Christmas`, not Christmas Eve).
- Regional variants (e.g. Diwali observed on Amavasya vs the day after) are not modelled; the window covers them.

## Festivals and windows

`Festival` (`core/domain/.../relive/Festivals.kt`) lists the festivals the app knows. Each has a **window**: the
number of days on either side of the date on which a memory still counts as "this festival" (Diwali lasts five days;
Ganesh Chaturthi ten). Names are string resources `festival_<key>` in `core/ui` (`festivalName(f)` /
`festivalNameRes(f)` in `core/ui/components/FestivalLabel.kt`), so they translate like everything else.

| Key | Name | Window (± days) |
|-----|------|-----------------|
| `diwali` | Diwali | 3 |
| `holi` | Holi | 2 |
| `ganesh_chaturthi` | Ganesh Chaturthi | 5 |
| `dussehra` | Dussehra | 2 |
| `raksha_bandhan` | Raksha Bandhan | 2 |
| `janmashtami` | Janmashtami | 2 |
| `gudi_padwa` | Gudi Padwa | 2 |
| `makar_sankranti` | Makar Sankranti | 2 |
| `eid_al_fitr` | Eid al-Fitr | 2 |
| `eid_al_adha` | Eid al-Adha | 2 |
| `guru_nanak_jayanti` | Guru Nanak Jayanti | 2 |
| `christmas` | Christmas | 2 |
| `new_year` | New Year | 1 |
| `independence_day` | Independence Day | 0 |
| `republic_day` | Republic Day | 0 |

Adding a festival: add the enum entry, a `festival_<key>` string in all locales, a `MAP` entry in the generator,
regenerate the CSV and extend `FestivalsTest`. The `when` in `festivalNameRes` is exhaustive, so a missing string
fails to compile.

## How the app uses it

A single `Festivals` instance is provided by Hilt (`DataModule.festivals()`, and `TestDataModule` for the smoke test)
and injected where needed.

- **Titles** (Quick Save, `feature/capture/QuickSaveViewModel`): when the pre-filled date is an exact day,
  `festivals.primary(date)` names the festival whose window holds it (the closest when two overlap) and
  `PolishEngine.titleFor(..., festival = name)` produces "Diwali 2024 with Aai" instead of "31 Oct 2024 with Aai".
  Month-only, year-only and fuzzy dates never get a festival title.
- **Relive** (`feature/relive/ReliveViewModel`): `festivals.rewind(today)` gives, while a festival's window is on,
  the same festival's windows in earlier years; `MemoryRepository.inDayRanges` loads those memories with one query
  and Relive shows "This Diwali, years ago" with an "N years ago" label on each card (hidden when there is nothing).
  Outside any window, if the next festival is 1–14 days away a small card says "Diwali in 12 days — Diwali photos
  from earlier years will show up here."
- **Reminders** (`feature/relive/notify/OnThisDayWorker`): on a festival's exact date the daily run (when "On this
  day" reminders are on) posts "Happy Diwali! Add today's photos to Yaadein". `Reminders.festivalToday` reads only
  the bundled table, so, like the rest of the digest, it works while the PIN-locked vault is closed; tapping opens the
  app.
- **Timeline filter** (`TimelineFilter.festival`, `MemoryRepositoryImpl.buildQuery`): the Filters sheet has a
  Festival row (one chip per festival); the query adds `AND (start_epoch_day BETWEEN a AND b OR …)` over
  `festivals.windows(festival)`, i.e. every year's window 2010–2035, and an active-filter chip shows the festival's
  name.
